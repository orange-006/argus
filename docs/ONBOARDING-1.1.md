# Argus 1.1 新手使用改造

## 目标

用户不必先阅读 README、查找初始密码、搜索订阅地址、填写模型接口，就能创建监测并理解首次结果。交付的是功能与自动化验证；没有把内部测试当作真实非技术用户可用性测试。

## 实施设计

新装：启动器生成本机一次性安装令牌，浏览器访问时写入会话并立即移除 URL 中的令牌；只有环回访问且持有有效令牌可以创建首个管理员。24 小时过期，重启启动器更新有效期。账号创建是原子领取过程，已有账号不能被首次向导重置。新装不产生明文首次密码文件。

引导：用途、行业、名称；来源选择；确认与开始。品牌别名不自动猜测，用户可明确补充。通知默认关闭、风险人工审核、基础识别可离线运行。只有显式选择允许导入时可以跳过来源。每次向导提交带会话随机键，同一提交幂等，创建新监测生成新键。

来源库：SourcePreset 保存名称、固定地址、分类、范围、内容级别、检查日期、使用说明和默认频率。发布前实际检查通过的四个公开源：阮一峰博客（Atom）、IT之家（RSS）、Solidot（RSS）、中国新闻网滚动新闻（RSS）。这是连通性与解析检查，不等于商业数据授权。新增到项目后由真实采集任务再次检查，不把预检查状态当作用户的当前连接状态。项目加来源模板唯一，重复添加不重复采集入口。

首次结果：实际来源内容与品牌提及分别统计。状态包括等待导入、采集中、分析中、连接失败、暂停、无匹配、部分成功、已完成。浏览器每三秒获取当前空间的状态；失败保留现有结果并提示；自动更新最多六分钟，后台继续工作。全程不补充虚假内容。成功完成首次检查与分析后后台自动生成首份日报，无命中也可显示真实覆盖。

体验隔离：每个用户拥有自己的 demo_owner 空间，不与真实 Membership 共享业务内容。会话中的体验 ID 需要服务器按归属校验。体验不连接外部来源、不调用 AI、不发送通知，限制同时在视图与服务层落实。角色使用体验分析员，不授予真实空间管理员权限。

升级：添加字段和数据迁移，不重置账号、项目、配置或密钥。只有来源全部为演示、内容全部标记演示的旧项目才自动移入管理员的体验空间；任何混合真实来源/内容的项目原样保留，避免误搬客户数据。迁移无反向自动搬回操作，升级前备份。

UI：常用导航保留工作台、内容、事件、审核和报告；开始设置、来源库、微信提醒直接可见；项目、手工来源地址、模型和运行日志放到“管理与高级设置”。

## 验收

自动化验证账号首次领取、既有账号保护、跨空间访问、向导幂等、来源重复、未授权来源、无匹配解释、报告自动生成、体验归属及外发阻断；浏览器验证真实新装和真实公开源采集、零命中报告、体验进入退出与手机布局。

后续仍需邀请至少五位非技术用户实际试用，记录独立完成率、用时和卡点。五分钟完成目标是产品目标，不能由自动化测试推定已达成。
