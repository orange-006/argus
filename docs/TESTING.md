# 自动化测试

## 业务与安全回归

执行 `.venv\Scripts\python.exe manage.py test core --verbosity 2`。测试用隔离数据库；不要使用 --keepdb 混淆旧状态。覆盖登录、空间隔离、角色权限、CSRF、导入批次回滚、去重、规则和 AI 输出校验、相似事件、拆分、通知、免打扰、任务恢复、报告、CSV 注入防护及首次使用与体验隔离。

外部 HTTP、AI 和微信在集成测试中由可控桩替代，以验证状态机和错误分支；这不等于真实供应商联调。另行实测 RSS 公网可用性并记录。没有有效微信和模型凭证时不能声称真实发送已通过。

## 浏览器端到端

在测试实例中执行，**会新增测试项目、内容、报告和只读账号，并修改测试空间的通知群名与启停配置**。不会发送真实微信消息。

准备：`npm install`，`npx playwright install chromium`。Windows 安装了 Chrome 时可设置 ARGUS_CHROME 指向 chrome.exe，使用已有浏览器。

单独测试实例：复制项目代码到测试目录，重建虚拟环境，设置 `ARGUS_PORT=8767`、`ARGUS_NO_BROWSER=1` 后运行 start.py。测试数据与正式 data 分开。第二个终端在同一测试目录设置 `ARGUS_TEST_URL=http://127.0.0.1:8767`，执行 `npm run test:e2e`。默认从测试目录 data/首次登录.txt 读取账号；密码已改时使用 ARGUS_TEST_USER / ARGUS_TEST_PASSWORD 环境变量。密码不写进输出。

验证：登录 → 创建品牌 → CSV 上传 → 等待后台分析 → 事件归并 → 风险审核 → 处理备注 → 日报 → CSV 下载 → 通知配置 → 只读成员。检查 11 个页面在 1440、1024、390、320 像素下是否溢出。结果和截图保存在 test-results/。

## 运行验证

1. 完整启动器启动 Web 和 Worker，检查 /health/ 与后台心跳。
2. 真实公网 RSS 完成首次采集并重采去重。
3. 备份数据库，并在隔离目录验证数据库完整性和密钥可解密。
4. 停止并重新启动服务，确认项目、事件与报告仍在。

本次交付的实测结果记录在 docs/TEST-REPORT.md；容量、准确率和生产可用性如未实测会明确列为未验收，不能由功能测试推出。

## 1.1 首次使用浏览器测试

`npm run test:onboarding` 只针对全新、隔离的测试数据目录运行。先设置 ARGUS_DATA_DIR 指向独立目录、ARGUS_PORT=8767、ARGUS_NO_BROWSER=1，启动 start.py。第二终端设置 ARGUS_TEST_DATA_DIR 为相同目录、ARGUS_TEST_URL=http://127.0.0.1:8767 后运行测试。脚本从本机一次性令牌创建测试账号，无需明文初始密码文件。测试会真实请求预置中国新闻网订阅，并检查来源内容与品牌零命中分开、首份日报和体验隔离。

账号已经创建的测试目录不可再次用作全新首次安装测试，需为下次测试选择另一个空目录。不要指向正式 data。测试结果在 test-results/v1.1/。这是自动化流程验证，不替代五位非技术用户的实际可用性试验。
