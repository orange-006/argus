# Argus 1.0 架构与设计

## 已实施决策

Windows 本机无 Docker，因此交付 Django 5.2 + SQLite + Waitress，本机一个 Web 进程和一个受监督 Worker 子进程。后台任务表同时作为业务 Outbox；轮询调度每 20 秒执行，任务每 2 秒检查。没有引入 Celery/RabbitMQ，避免安装和运营负担；云端规模部署另行迁移。

Web 接收请求、校验空间与权限、持久化业务和任务；Worker 执行采集、分析、发送及报告。任务 claim 使用带状态条件的原子 UPDATE，租约五分钟，失败指数退避最多三次。单机使用一个 Worker，SQLite 串行写锁依赖事务和 30 秒 busy timeout。长任务应低于租约；大规模采集不在本版本目标内。

## 数据模型

- Workspace → Membership → User：客户空间与角色。
- Workspace → Project → Source → Content：来源按项目和空间隔离，不跨客户共享上传数据。
- Source → SourceRun：每轮读取/新增数与错误。
- Project → Event → EventItem → Content：事件证据，一条内容只归属一个事件。
- Workspace → NotificationConfig、AIConfig：配置与加密密钥。
- Event/Report → Delivery：业务幂等键、目标版本、状态和尝试次数。
- Project → Report：日期和修订唯一，JSON 快照不可变。
- Content → AnalysisRun：内容摘要、规则、模型和提示词版本构成复用键，保存 token 用量。
- Workspace → Job、AuditLog：任务、错误和审计。

## 内容与分析

去重键是来源加外部 ID 摘要，优先 guid、链接，再用内容摘要。当前不保存已入库帖子后续编辑版本，重复 ID 不覆盖原始记录；这是一项明确限制。最多读取 RSS 最近 300 条，不能据此声称补齐历史。

规则匹配项目名和别名，排除词为硬排除；负面词只能产生辅助线索。AI 采用用户配置的兼容 chat/completions HTTPS 接口，严格校验证据字符串与分类枚举。相同版本成功结果复用，失败结果不反复请求；修改模型、规则或内容版本形成新的签名。每日以记录数限制请求，显示 token 数，不虚构货币费用。

相似事件在项目内最近两天、同问题类别候选中使用归一化标题相似度 ≥0.60 自动归并；不等同于跨平台准确事件识别。详情页可人工拆分。风险等级由规则与人工审核，紧急核实必须由人工设定。模型没有发送或数据库工具权限。

## 网络与内容安全

RSS 和模型请求解析 DNS，拒绝任意非公网地址；连接绑定已经校验的 IP，TLS 使用原域名 SNI 与主机名验证；重定向重新校验；不读取系统代理。只允许 HTTP/HTTPS 标准端口，POST 只使用 HTTPS、不自动跟随重定向。限制连接/读取超时和响应体积。RSS 拒绝 DTD/ENTITY 声明。原始内容作为普通文本输出、模板默认转义。

通知仅允许 qyapi.weixin.qq.com/cgi-bin/webhook/send 的受限 key 格式，凭证使用本地 Fernet 密钥加密，不进入模型、日志或导出。模型文本发送前掩码手机号；本地原始证据受空间权限保护。应用默认环回监听，不公开管理服务。

## 通知状态机

审核通过 → 创建 Delivery → 目标版本检查 → 启停/验证/门槛 → 免打扰 → 发送中 → 接口已接收 / 发送失败 / 结果未知。

已接收与结果未知不自动重发；进程在发送中断后恢复也会转结果未知。配置更换后旧目标版本不能改发到新群。失败人工重试；未知结果补发需确认重复风险。接口接收不是成员已读。

免打扰支持跨日，结束后继续处理每条有效通知；**当前没有自动合并多事件为一条提醒**，首版以事件级去重和限流队列为准。日报按当天项目生成，一天自动任务唯一；手动生成新增修订，原报告不变。

## 后续扩展条件

持续并发写入、客户数或队列积压超过本地版能力时，再迁移 PostgreSQL 与专用队列；数据库 JSON 结构与业务服务保持独立。社交平台适配器需要先解决真实凭证、允许用途、持续可用性和字段完整性，不能仅用界面占位宣称支持。
